DEFENSE IN DEPTH

Security status is configuration-dependent

This console never claims encryption, rotation, or audit integrity is active until the server confirms it. A missing key or integrity mismatch must raise an explicit warning, not an empty dashboard.

ENCRYPTION AT REST

AES-256-GCM

Use vetted platform crypto with a 32-byte key supplied outside the database. Keep TLS enabled in the deployment proxy for data in transit.

Shell · key generation example
openssl rand -hex 32

Store the resulting key in a managed secret store or protected environment. Never paste it into the browser or commit it.

APPEND-ONLY AUDIT

Integrity chain

Audit entries should chain each event to the previous digest. This detects edits in the chain; it is not a blockchain and is not tamper-proof against an attacker who can rewrite the entire store.

Live integrity status requires authenticated server check.

LOGIN DEFENSE

Progressive throttling

Use progressive delays and temporary lockouts for repeated failures, generic public errors, and a separate secure recovery flow. Alert administrators without logging credentials or sensitive request bodies.

  • Login and permission changes audited
  • Exports, deletions, approvals and provider changes audited
  • Tokens and sensitive payloads redacted
  • Recovery and restore drills documented
INCIDENT RESPONSE

Contain, preserve, recover

  1. Restrict affected credentials and preserve logs.
  2. Rotate secrets from a trusted device and inspect access history.
  3. Restore from a verified backup; validate audit-chain continuity.
  4. Record scope, remediation, and follow-up tests.

Optional decoy records must be isolated from normal retrieval, training, and user answers.

DEVELOPER DOCUMENTATION

Help & API guide

Versioned gateway contract, permissions and safe integration practices.

Authentication

App routes use X-Vibes-API-Key. Keys are app-bound and must be sent over HTTPS. Never place gateway admin or provider keys in browser code or Android resources.

Common routes

POST/api/v1/appsRegister the key's bound app
PUT/api/v1/apps/{appId}/heartbeatUpdate last-seen status
GET/api/v1/appsDiscover app metadata

Scopes, errors and rate limits

Grant only the required scopes, such as apps:register, apps:heartbeat, ai:chat, ai:models, learning:feedback, or agents:run. Treat HTTP 401/403 as authentication/permission failures, 429 as throttling, and 5xx as temporary server errors. Honor Retry-After if present and use bounded exponential backoff.

Exact quotas depend on server configuration; no fixed rate limit is promised here. Breaking contract changes must use a new API version.
